ASD-STE100（Simplified Technical English，简化技术英语）是欧洲航天防务工业协会为航空维修手册制定的控制语言规范：用有限的词、最简单的语法，把意思说到不可误解。这一页用它的核心纪律，把阅读器里 36 篇文章的核心观点各压缩成几句"零歧义"英文，附中文对照。

本页执行的规则：

  • 一句只说一件事；描述句不超过 20 个词
  • 主动语态；只用一般现在时/过去时
  • 一个词只用一个含义；选最常用的词（用 use，不用 utilize）
  • 不用习语、比喻、口语（原文的比喻都已转成直白说法）
  • 每条观点独立成立，可以单独读

诚实声明：本页遵循 ASD-STE100 的核心语法与词汇纪律；未逐词对照官方批准词表（Issue 8 约 900 个批准词）。术语（MCP、harness、sandbox）作为专有名词保留。

1地基：理解 AI 工作流与智能体
01AnthropicBuilding effective agents
  1. A workflow follows a path that developers write in code. An agent plans its own path and selects its own tools.工作流的路径由开发者在代码里写死；智能体自己规划路径、自己选工具。
  2. Start with the simplest pattern. Add complexity only when the task needs it.从最简单的模式开始；任务确实需要时才加复杂度。
  3. Five workflow patterns cover most needs: prompt chains, routing, parallelization, orchestrator-workers, and evaluator-optimizer.五种工作流模式覆盖大多数需求：提示链、路由、并行化、编排者-工人、评估者-优化者。
  4. An agent needs a strong model, good tools, and clear instructions. A framework is optional.智能体需要强模型、好工具、清晰指令；框架不是必需品。
  5. The page now carries an official note. The tool details changed after December 2024. The core concepts stay current.页面已带官方提示：工具细节在 2024 年 12 月后已变化；核心概念仍然有效。
02OpenAIA practical guide to building agents
  1. Pick tasks with many valid paths. The agent must adapt. Errors must cost little.选"路径多解、必须随机应变、容错成本可接受"的任务。
  2. Build one agent first. Give it a model, tools, and clear instructions.先建单个智能体：模型、工具、清晰指令三件套。
  3. Grow to many agents step by step. Use a manager pattern, or let agents hand tasks to each other.再逐步扩到多智能体：管理者模式，或智能体互相交接。
  4. Put three guardrails in place: an isolated sandbox, a human handoff, and system-level checks.设三道护栏：隔离沙箱、人工接管、系统级防护。
03OpenAINew tools for building agents
  1. The Responses API is the new base for model calls.Responses API 成为模型调用的新基座。
  2. Built-in tools search the web, search files, and control a computer.内置工具能搜网页、搜文件、操作计算机。
  3. The Agents SDK is open source. Handoffs, guardrails, and tracing come as standard parts.开源 Agents SDK 把交接、护栏、追踪做成标准件。
04PiPrompts are code, .json/.md files are state
  1. Treat prompts as code. Put them in version control. Review and roll back each change.把提示词当代码：进版本库，可评审、可回滚。
  2. Treat .json and .md files as agent state. Keep the state explicit and open to inspection.把 .json/.md 文件当智能体状态：显式、可检查。
  3. Reliable behavior comes from visible state. It does not come from a long chat history.可靠的行为来自可见的状态，不来自很长的聊天历史。
2核心机制：上下文、工具与执行环境
05AnthropicEffective context engineering for AI agents
  1. The context window is a budget. Attention gets thin as the context grows.上下文窗口是预算；上下文越长，注意力越稀。
  2. Three methods manage the budget: compress old steps, write structured notes, and move work to sub-agents.三种手段管理预算：压缩旧步骤、写结构化笔记、把工作分流给子代理。
  3. Load information late. Give an index first. Fetch the full text only when needed.信息晚点加载：先给索引，需要时才取全文。
06AnthropicThe "think" tool
  1. The think tool does nothing. It only gives the model a pause between tool calls.think 工具什么都不做，只在工具调用之间制造一个停顿。
  2. In the pause, the model reviews its state. Accuracy improves on hard tool tasks.停顿中模型复盘当前状态；困难工具任务上的准确率因此提升。
  3. A change in process timing can lift performance more than a new model.改流程时机带来的提升，可能大过换一个模型。
07AnthropicWriting effective tools for agents — with agents
  1. A tool description is documentation for a model. Write it like documentation.工具描述是写给模型的文档；请按文档标准写。
  2. Give each tool a clear name, one clear purpose, and typed inputs. Return short, structured results.每个工具：名字清楚、用途单一、输入有类型；返回短而结构化的结果。
  3. Flag every failure with a plain reason. Never return a long raw dump.每个失败都给明原因；不要返回大段原始数据。
  4. Use one agent to test and improve the tools of another agent.用一个智能体去测试并改进另一个智能体的工具。
08PiMCP vs CLI: Benchmarking Tools for Coding Agents
  1. The author ran the same coding tasks through MCP tools and through plain CLI commands.作者让同一批编码任务分别走 MCP 工具和普通 CLI 命令。
  2. Well-made CLI tools matched or beat the MCP tools in the benchmark.基准结果：做得好的 CLI 不输甚至胜过 MCP。
  3. Interface clarity decides tool quality. The protocol form matters less.接口清晰度决定工具质量；协议形态没那么重要。
  4. Run your own small benchmark before you pick a tool layer.选工具层之前，先跑自己的小基准。
09PiWhat if you don't need MCP at all?
  1. Scripts plus a shell often make a simpler integration layer.脚本加 shell 往往就是更简单的集成层。
  2. MCP adds cost: more tokens, more code to maintain, and harder debugging.MCP 带来三种成本：更多 token、更多维护代码、更难的调试。
  3. Choose the layer that you can debug fastest.选你能最快调试的那一层。
10AnthropicCode execution with MCP
  1. Show MCP tools to the model as a code API on the file system.把 MCP 工具呈现为文件系统上的代码 API。
  2. The model writes code that calls the tools. It loads only the definitions it needs.模型写代码来调用工具；只加载需要的定义。
  3. Intermediate results stay in files. Token use falls sharply.中间结果留在文件里；token 消耗大幅下降。
11AnthropicIntroducing advanced tool use
  1. Programmatic tool calling lets the model call tools inside a code loop.程序化工具调用让模型在代码循环里连续调工具。
  2. Tool search finds the right tool from a large set, on demand.工具搜索按需从大工具集中找到合适的那个。
  3. These platform features scale the tool count from tens to hundreds.这些平台能力把工具规模从几十个扩到几百个。
12AnthropicEquipping agents for the real world with Agent Skills
  1. A skill is a folder with instructions, scripts, and files for one domain.技能是一个文件夹：某领域的指令、脚本与资源。
  2. The agent reads a short summary first. It loads the full skill only when needed.先读短摘要，需要时才加载全文（渐进披露）。
  3. Teams can share skills. Skills turn team knowledge into reusable agent parts.技能可共享：把团队知识变成可复用的智能体部件。

4长时运行与可靠性
22AnthropicEffective harnesses for long-running agents
  1. A long job spans many context windows. Each new window starts with no memory.长任务跨多个上下文窗口；每个新窗口都从零记忆开始。
  2. The harness writes handover notes. The next window reads them before it works.harness 写交接笔记；下一个窗口先读再干活。
  3. Three parts help: a first-turn briefing, a checklist, and checkpoints.三件套：首回合简报、检查清单、检查点。
  4. The harness is a second lever, beside the model itself.harness 是模型之外的第二个杠杆。
23AnthropicHarness design for long-running application development
  1. The team improved long autonomous coding with harness changes, not with model changes.团队靠改 harness（而非换模型）提升长时自主编码。
  2. They tuned prompts, tools, and process steps. The same model scored far above its baseline.调提示词、工具与流程步骤；同一个模型远超基线。
  3. Treat harness design as an engineering discipline with tests.把 harness 设计当作带测试的工程学科。
24AnthropicScaling Managed Agents: Decoupling the brain from the hands
  1. Harnesses carry assumptions about what the model cannot do. These assumptions age as models improve.harness 内含"模型不会什么"的假设；模型进步后假设会过时。
  2. Anthropic split the agent into three interfaces: brain, hands, and session.Anthropic 把智能体拆成三个接口：大脑、双手、会话。
  3. Each part can fail or be replaced alone.每个部件可以单独失败、单独替换。
  4. Stable interfaces let the model change under them without a rebuild.接口稳定，模型更替时上层不必重建。
25AnthropicBeyond permission prompts: sandboxing
  1. Old flow: ask the user at every step. New flow: isolate first, then give freedom.旧流程每步问人；新流程先隔离、再放权。
  2. The sandbox limits file access and network access.沙箱限制文件访问与网络访问。
  3. Autonomy is safe when the damage from one failure stays small.单次失败的损失可控时，自治才是安全的。
26AnthropicHow we built Claude Code auto mode
  1. Users approved 93 percent of permission prompts. Careful checking faded with each click.用户批准了 93% 的权限弹窗；审查注意力随点击递减。
  2. Claude Code now uses classifiers to decide some permission requests.Claude Code 现在用分类器决策一部分权限请求。
  3. The classifiers handle simple decisions. The user decides the hard ones.分类器管简单决策；人只管难的。
27AnthropicDemystifying evals for AI agents
  1. Agents run many turns and change state. Single test points cannot grade that.智能体多轮运行且状态可变；单点测试无法评分。
  2. Build three layers: custom graders, trace grading, and production observation.搭三层：自定义评估器、轨迹评估、生产观测。
  3. Evals pay off over time. Prompt changes stop being guesses.评估的价值随时间复利；改提示词不再是猜。
